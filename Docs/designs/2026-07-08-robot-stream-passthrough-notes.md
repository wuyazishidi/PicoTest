关联：`Docs/designs/2026-07-08-vst-passthrough-demo.md`（透视复现 demo）、`Docs/designs/2026-07-02-webrtc-stereo-dome.md`（WebRTC 传输）、`Assets/Experiments/Exp-VstPassthrough/`（ImuCamRig/capture 模式实现）

## 一、机器人画面能否达到 VstPassthroughDemo 的效果

**结论：可以，显示端管线源无关**（decisions.md：WebRTC 方案 = 只换数据源、复用穹顶）。起作用的三要素——鱼眼模型反查、外参换算、按捕获时刻位姿锚定——参数给齐即可迁移。但"等同"要拆开：

### 直接达到
- **角度 1:1 与去畸变**：shader 视线方向反查像素，只吃内参 K + 径向畸变 k1..k6（等距鱼眼族；OpenCV `cv::fisheye` k1-k4 高阶补零即可）。
- **转头稳定性（机器人场景反而更容易）**：机器人头不动/慢动时穹顶 WorldLocked——转头环顾已收到的画面，**转头零延迟零拖影，比本地透视还干净**（XRLiveDemo 选 WorldLocked 的原因）。
- **外参对齐**：`ImuCamRig` 自标定换算（不信 T 字段名、两种语义打分自选、头系基从标定自身构造）对任何双目刚体组成立。

### 有条件成立
1. **深度 1:1 取决于基线**：必须 ≈ 人眼 IPD（64mm 上下）。基线 128mm 世界缩半、32mm 放大一倍——几何事实，软件不可补。**参数到手先看这项**。
2. **机器人头会转时**：需帧同步的机器人头位姿（见第二节），否则云台一动画面游移。
3. **画质**：WebRTC 720p/眼 + 有损编码 vs 本地 RAW 1280×960，对齐不受影响，观感打折。

### 达不到但问题不大
- **内容延迟**（编码+网络+解码 100-300ms vs 本地 ~80ms）。延迟体感分两种：**转头延迟**（最晕）被 WorldLocked 消掉；剩**手眼延迟**影响操作精度、不影响立体稳定性。旋转可重投影，内容变化不能无中生有。

### 真正的拦路虎
不是光学是传输：com.unity.webrtc 在 PICO 的硬解/兼容性未真机验证（decisions.md 遗留风险）。光学半边已被 VstPassthroughDemo 验完，参数到手第一件事应是打通真机收流。

## 二、是否需要视频帧时间戳 / 如何做补偿

**分情况：云台不动不需要；云台会动必须要。** 且要的本质不是时间戳，是**每帧 ↔ 拍摄时刻云台位姿的对应关系**，时间戳只是建立对应的手段之一。

### 问题本质
穹顶渲染要回答"这帧画面挂在哪个朝向"。挂错则云台运动期间画面漂移：
- **机器人头静止**：WorldLocked 挂死即最优解。时间戳仅用于延迟统计。
- **机器人头会转**：帧到达时云台已不在拍摄朝向。按当前朝向挂 → 伺服期间漂移；按"到达时刻 − 固定延迟"猜 → 网络抖动即猜错。正解 = **挂到拍摄那一刻的云台朝向**（VstPassthroughDemo capture 模式的机器人版：本机头位姿环形缓冲 → 换成机器人位姿遥测，接收端查找/锚定机械已实现）。

### 配对方案（按优劣）
1. **最好：位姿随帧走**。发送端每帧经 WebRTC DataChannel（或 RTP 头扩展/SEI）带 `{frame_id, 云台四元数}`。**不需要时钟同步**，天然免疫抖动（每帧带真值）。
2. **次好：同源时钟双流**。帧带 `capture_ts`（机器人单调钟），位姿流独立发 `{ts, pose}` 同钟，接收端按 ts 插值配对。**只要求机器人自己时钟自洽，不要求与头显对钟**（配对发生在机器人时间轴上）。
3. **兜底：固定延迟估计**（demo 的 `latencyMs` 旋钮）。云台慢 + 网络稳时勉强可用，仅作协议字段缺失的退路。

### 另两个"效果好"的杠杆
- **传输侧压延迟**（收益大于几何补偿）：playoutDelay≈0、jitter buffer 调小、编码 zerolatency/短 GOP、码率留头防排队。300ms→120ms 比任何重投影都明显。
- **伺服策略压需求**：慢伺服 + 死区（死区内全靠世界锁环顾）——云台动得越少越慢，位姿补偿负担越小。

### 给机器人侧的最小协议增量
```
视频流：SBS 双目帧（现有）
随帧数据（DataChannel）：{ frame_id, capture_ts(机器人单调钟, ns), head_pose(qx,qy,qz,qw[, 位置]) }
```
有此一条，接收端即 capture 模式直接移植；`capture_ts` 顺带可测玻璃到玻璃延迟（调传输参数的硬数据）。

### 参数清单（机器人侧提供）
每眼 K(3×3)、畸变系数 + 模型名、双目基线、每眼到机器人头/基座的 T（注明方向语义，接收端仍会自检）、分辨率；云台会动则加：帧 `frame_id`/`capture_ts` + 同钟头位姿（随帧或独立流）。
